# AWS コスト見積もり

月額の AWS コスト見積もりを作成します。前提条件を明確にすることを最優先にしてください。ユーザーが検証・調整できる見積もりは、検証不可能な精緻な数字より価値があります。

## 入力

以下のいずれも見積もりの入力として受け付けます。
- 自然文の構成説明（例: 「ap-northeast-1 に ALB と t3.medium の EC2 3 台、RDS Postgres db.t3.small Multi-AZ、S3 500GB」）。
- Terraform ファイル（`.tf`）。`Read` で読み、`resource` ブロックからリソースを推定する。
- CloudFormation / CDK の出力（`.yaml`、`.json`）。
- ユーザーが文章で説明したアーキテクチャ図。

入力が曖昧な場合（リージョン未指定、トラフィック量不明、ストレージ容量不明など）は妥当なデフォルトを採用し、**採用したデフォルトは漏れなく「前提」セクションに列挙して**、ユーザーが後で修正できるようにします。

## 料金データの取得（AWS Knowledge MCP）

単価は記憶や推測ではなく、まず **`aws-knowledge` MCP サーバー**（本プラグイン同梱のリモート MCP、`https://knowledge-mcp.global.api.aws`）で公式の料金ページを参照して取得します。

- ドキュメント検索ツールで対象サービス・リージョンの料金ページを探し、読み取りツールで本文（単価表）を取得する。例: 「EC2 オンデマンド料金 ap-northeast-1」「RDS PostgreSQL 料金」「S3 ストレージ料金」。
- 取得した単価は、見積もり本文で**根拠として参照元（料金ページ）に触れて**裏付ける。
- MCP が利用できない／対象の単価が引けない場合は、その項目を「未確認」と明示し、記憶ベースの概算は範囲（$X〜$Y）で示す。**精緻な数値を捏造しない。**

## 進め方

1. **インベントリ** — 課金対象リソースをサービス別にすべて列挙する。
2. **前提** — リージョン、利用量、データ転送量、リクエスト数、ストレージ増加量、月あたりの稼働時間（デフォルト 730 時間）、Savings Plans / RI の有無（デフォルト: なし → オンデマンド）を明記する。
3. **料金参照** — 各サービスの単価を `aws-knowledge` MCP で取得する（上記「料金データの取得」参照）。引けたものは実価格、引けないものは「未確認」と区別する。
4. **見積もり** — 各項目ごとに `数量 × 単価 = 月額` の形式で内訳を出す。選択したリージョンの最新のオンデマンド料金を使う。単価が不確かなものは、はっきり「不確か」と言って範囲で示す（無理に精緻な数値を書かない）。
5. **合計** — USD で合計。日本拠点ユーザー向けには指定レートで JPY も併記してよい。
6. **感度分析** — 総額を最も大きく動かす項目を 1〜3 個挙げ、それぞれの削減策（Savings Plans、Graviton、S3 IA、適切なサイジング）を示す。

## 出力フォーマット

```
## AWS コスト見積もり — <タイトル>

**リージョン:** <region>     **料金モデル:** オンデマンド     **期間:** 月額（730 時間換算）

### 前提
- <採用したデフォルトや推定値を 1 行ずつ列挙>

### 内訳
| サービス | リソース | 数量 | 単価 | 月額 |
| --- | --- | --- | --- | --- |
| EC2 | t3.medium (ap-northeast-1) | 3 × 730h | $0.0544/h | $119.14 |
| ... | ... | ... | ... | ... |

**コンピュート小計:** $X
**ストレージ小計:** $X
**データ転送小計:** $X
**その他:** $X

### 合計
**≈ $XXX / 月**（≒ ¥XX,XXX、¥150/USD 換算）

### 総額を最も動かす要素
1. <項目> — <削減策>
2. ...

### 含めていないもの
- <意図的にスコープ外にしたもの: サポートプラン、Marketplace AMI、税金など>
```

## 原則

- **リージョンは必ず明記** する。リージョンによって価格が大きく異なる。日本拠点ユーザーで指定がなければ `ap-northeast-1`（東京）をデフォルトに、それ以外は一度確認したうえで `us-east-1` をデフォルトにする。
- **料金モデルも必ず明記** する（オンデマンド / Savings Plan / Spot）。デフォルトはオンデマンド。
- 無料利用枠: 本番ワークロードの見積もりでは原則考慮しない。ユーザーから依頼があった場合、または明らかに無料枠で収まるワークロード（「個人ブログで 1 日 100 リクエスト」など）の場合のみ言及する。
- データ転送は最も見落とされやすい項目。ユーザー向けのサービスではアウトバウンド転送を必ず含める。
- これは見積もりであって見積書ではない。レポートの末尾に必ず次の一文を入れる: *「確定金額は [AWS Pricing Calculator](https://calculator.aws/) で再確認してから判断してください。」*
